# Обследование ЛЭП в Gazebo

Задача A «Почти как на финале», НТО 26/27. Дрон облетает три опоры, проверяет 12 изоляторов и садится там, где взлетел. [Условие задачи](https://new.contest.yandex.ru/contests/100384/problems?id=420131%2F2026_11_03%2FBtB4sgtoFW)

## Запуск

Ubuntu 24.04 с графическим сеансом. `setup.sh` установит ROS 2 Jazzy, Gazebo Harmonic и OpenCV.

```bash
git clone https://github.com/godplayTty/nto-lep-gazebo.git lep-inspection
cd lep-inspection
./setup.sh
./run.sh
```

Откройте панель и нажмите **Старт**. В терминале появится `Запуск mission.py`. **Стоп** начинает посадку в текущей точке. **Kill switch** выключает роторы. После любой из этих команд для следующего полёта запустите `./run.sh` заново. [Панель на порту 8080](http://127.0.0.1:8080)

```bash
./run.sh --seed 20261112             # Расстановка из видео
./run.sh --headless --seed 20261112  # Тот же мир без окна Gazebo
```

Без `--seed` скрипт печатает случайно выбранный seed. В Dev Container сразу используйте команду с `--headless`. Для доступа с хоста пробросьте порт 8080.

## Что происходит в полёте

На полу 234 маркера ArUco. `generate_world.py` строит сетку в Gazebo и пишет её координаты в `generated/aruco_map.json`. По углам маркеров на кадрах нижней камеры дрон определяет своё положение.

На каждой опоре есть синяя табличка. По её размеру, высоте и положению в кадре скрипт рассчитывает центр основания и определяет лицевую сторону. Затем проверяет цвет в четырёх местах крепления изоляторов. При взгляде сзади №1 виден слева в кадре. Номер у него прежний.

| Ярус | Слева спереди | Справа спереди |
| --- | --- | --- |
| Верхний, 1,2 м | 2 | 1 |
| Нижний, 0,9 м | 3 | 4 |

Провода соединяют изоляторы с одинаковыми номерами. Чёрный означает «исправен», коричневый — «износ», красный — «дефект». После осмотра дрон пролетает над последней опорой и возвращается к началу координат.

## Видео и проверка

В видео видно полёт, строку запуска `mission.py` в терминале и таблицу `/insulators` в браузере. Для своей записи включите **Follow** на модели `inspection_quad` в Gazebo. [Запись полёта](docs/mission.mp4)

```bash
source /opt/ros/jazzy/setup.bash
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
ros2 topic echo /insulators --qos-durability transient_local
```

В `/insulators` приходит `std_msgs/msg/String` с JSON в поле `data`. Пара `tower_id` и `number` определяет запись. Панель обновляет карту и таблицу по этому топику, а схему проводов берёт из эталона. Нода полёта читает карту маркеров и камеры.

| Данные | Где смотреть |
| --- | --- |
| Нижняя камера | `/camera/down/image`, `/camera/down/camera_info` |
| Фронтальная камера | `/camera/front/image`, `/camera/front/camera_info` |
| TF | `aruco_map → base_link → down_optical, front_optical` |
| Эталон для сравнения | `generated/reference.json` |

После посадки снимите результаты с панели и сравните их с эталоном. Допуск по центру опоры — 20 см.

```bash
curl -fsS http://127.0.0.1:8080/state |
  python3 -c 'import json,sys; print(json.dumps(json.load(sys.stdin)["results"]))' > /tmp/lep-results.json
python3 evaluate.py generated/reference.json /tmp/lep-results.json
```

Для seed `20261112` и `7287` проверка нашла 12 совпадений из 12. Максимальная ошибка центра — около 1 см. Посадку по **Стоп** и отключение роторов проверили отдельными запусками.
