# Обследование ЛЭП в Gazebo

Задача A «Почти как на финале», НТО 26/27. Квадрокоптер взлетает с площадки, осматривает три опоры и возвращается на старт. Цвета изоляторов меняются при каждой генерации мира. [Условие задачи](https://new.contest.yandex.ru/contests/100384/problems?id=420131%2F2026_11_03%2FBtB4sgtoFW)

## Как запустить

Нужна Ubuntu 24.04 с графическим сеансом. Скрипт установки подготовит ROS 2 Jazzy, Gazebo Harmonic и OpenCV.

```bash
git clone https://github.com/godplayTty/nto-lep-gazebo.git lep-inspection
cd lep-inspection
./setup.sh
./run.sh
```

Откройте [панель на порту 8080](http://127.0.0.1:8080) и нажмите **Старт**. В терминале появится строка о запуске `mission.py`. Пока дрон в полёте, повторный старт недоступен. **Стоп** сажает дрон там, где его застала команда. **Kill switch** сразу отключает роторы. После любой из этих двух команд перезапустите `./run.sh`, чтобы начать новую миссию.

Для повтора мира из видео запустите `./run.sh --seed 20261112`. Без `--seed` скрипт выбирает новое число и печатает его в терминале. Для запуска без окна Gazebo используйте `./run.sh --headless --seed 20261112`. Эту же команду можно выполнить в Dev Container без шага установки. Если симулятор запущен в виртуальной машине, перенаправьте порт 8080 гостя на хост.

## Что происходит в полёте

На полу 234 маркера ArUco. `generate_world.py` делает сетку в Gazebo и файл `generated/aruco_map.json` из одного списка маркеров. По нижней камере дрон определяет своё положение в этой системе координат.

Фронтальная камера ищет синюю табличку на каждой опоре. По её размеру, высоте и положению в кадре скрипт рассчитывает центр основания и определяет лицевую сторону. После этого он проверяет цвет в четырёх местах крепления изоляторов. Номера закреплены за самой опорой, поэтому при взгляде сзади правый и левый изоляторы сохраняют свои номера.

| Ярус | Слева спереди | Справа спереди |
| --- | --- | --- |
| Верхний, 1,2 м | 2 | 1 |
| Нижний, 0,9 м | 3 | 4 |

После осмотра дрон пролетает над последней опорой и возвращается к началу координат. В двух пролётах по четыре провода, каждый соединяет изоляторы с одинаковым номером. Чёрный изолятор считается исправным, коричневый означает износ, красный — дефект.

`mission.py` получает карту ArUco, изображения и параметры камер. Веб-панель строит опоры и таблицу по сообщениям из `/insulators`, а из `generated/reference.json` берёт только схему проводов. Координаты и цвета из эталона нужны скрипту `evaluate.py`, чтобы сравнить их с результатом уже после полёта.

## Видео и проверка

[Запись полёта](docs/mission.mp4) показывает Gazebo с камерой, которая следует за дроном, терминал с запуском `mission.py` и веб-панель с результатами `/insulators`. Чтобы записать свой прогон, включите **Follow** для модели `inspection_quad` в Gazebo и разместите панель и терминал рядом.

Вывод `/insulators` можно посмотреть и в отдельном терминале.

```bash
source /opt/ros/jazzy/setup.bash
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
ros2 topic echo /insulators --qos-durability transient_local
```

Топик содержит JSON в поле `data` сообщения `std_msgs/msg/String`. В текущем снимке результатов у каждой пары `tower_id` и `number` одна запись. При новых наблюдениях она уточняется.

Проверка после посадки сравнивает центры опор с допуском 0,2 м и сверяет номер, цвет и состояние каждого изолятора.

```bash
curl -fsS http://127.0.0.1:8080/state |
  python3 -c 'import json,sys; print(json.dumps(json.load(sys.stdin)["results"]))' > /tmp/lep-results.json
python3 evaluate.py generated/reference.json /tmp/lep-results.json
```

Изображения и параметры камер идут в `/camera/down/{image,camera_info}` и `/camera/front/{image,camera_info}`. В TF публикуются `aruco_map → base_link` и два преобразования от `base_link` к `down_optical` и `front_optical`.

После правок проверены миры `20261112` и `7287` на Ubuntu 24.04. В обоих прогонах найдены три опоры и все 12 изоляторов. Наибольшее отклонение центра опоры составило 0,010 м. Дрон пролетел над последней опорой и сел на площадке старта. Команды **Стоп** и **Kill switch** проверены в отдельных запусках.
