# Обследование ЛЭП в Gazebo

Решение задачи A «Почти как на финале» НТО 26/27. Для симуляции используется Gazebo Harmonic с физической моделью квадрокоптера и контроллером скоростей. ROS 2 Jazzy обрабатывает кадры с двух камер и выполняет миссию.

## Запуск

Нужна Ubuntu 24.04, на macOS можно использовать виртуальную машину с Ubuntu 24.04. Графический сеанс Ubuntu нужен для просмотра Gazebo и записи демонстрации. Клонируйте репозиторий.

```bash
git clone https://github.com/godplayTty/nto-lep-gazebo.git lep-inspection
cd lep-inspection
./setup.sh
./run.sh
```

В браузере того же компьютера откройте `http://127.0.0.1:8080` и нажмите **Старт**. Команда запускает `mission.py` и начинает обследование после подключения камер. **Стоп** прерывает обследование и запускает посадку на текущем месте. **Kill switch** отключает роторы в симуляторе. После остановки, аварии или отключения роторов перезапустите `run.sh` для новой миссии.

Чтобы повторить конкретный мир, возьмите `seed` из вывода генератора или `generated/reference.json`.

```bash
./run.sh --seed 20261111
```

Для запуска без GUI используйте `./run.sh --headless --seed 20261111`. В VS Code можно открыть проект в приложенном Dev Container и выполнить ту же команду без `setup.sh`. При запуске в Lima или на другой виртуальной машине перенаправьте локальный порт 8080 гостя на хост.

## Как работает миссия

- `generate_world.py` размещает решётчатые опоры, четыре подвесных изолятора на каждой и два пролёта по четыре провода. Направление линии, положение опор и цвета варьируются при каждом запуске. Описание 234 напольных маркеров `DICT_6X6_250` записывается в `generated/aruco_map.json` из тех же данных, что используются для геометрии пола.
- `vision.py` восстанавливает позу по углам ArUco из нижней камеры. На кадре фронтальной камеры ищет синюю табличку, рассчитывает положение центра основания и сторону опоры, затем проверяет цвет в проекциях четырёх штатных мест крепления.
- `mission.py` получает карту маркеров, кадры и параметры обеих камер. После взлёта последовательно ищет таблички, обследует опоры с лицевой стороны и возвращается к началу координат. В ROS публикуются `aruco_map → base_link → {down_optical, front_optical}` и `/insulators`. Координаты и цвета из `reference.json` используются только проверкой результатов. Веб-панель берёт из этого файла схему проводов.
- `dashboard.py` отдаёт карту и таблицу результатов. Таблица обновляется из `/insulators`. Каждая пара `tower_id` и `number` публикуется один раз в текущем снимке результатов, её значения уточняются по новым кадрам.

Камеры публикуют изображения и параметры в `/camera/down/{image,camera_info}` и `/camera/front/{image,camera_info}`. `/insulators` имеет тип `std_msgs/msg/String`. Поле `data` содержит JSON с `frame_id` и массивом `insulators`.

## Проверка и запись

Во втором терминале можно вывести результаты и дерево TF.

```bash
source /opt/ros/jazzy/setup.bash
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
ros2 topic echo /insulators --qos-durability transient_local
```

После завершения миссии сохраните полученные результаты и сравните их с эталоном.

```bash
curl -fsS http://127.0.0.1:8080/state |
  python3 -c 'import json,sys; print(json.dumps(json.load(sys.stdin)["results"]))' > /tmp/lep-results.json
python3 evaluate.py generated/reference.json /tmp/lep-results.json
```

Для записи разместите на одном экране окно Gazebo, окно веб-панели и терминал с `./run.sh` и выводом `/insulators`. В дереве объектов Gazebo выберите `inspection_quad` и включите **Follow**. Начните запись до нажатия **Старт** и завершите после посадки. Имя запускаемого файла `mission.py` появится в терминале после нажатия кнопки.

[Видео миссии в Gazebo](docs/mission.mp4) снято на мире с `seed=20261112`. В кадре одновременно видны квадрокоптер в Gazebo, запуск `mission.py` в терминале и результаты `/insulators` в веб-панели.

В Gazebo Harmonic на Ubuntu 24.04 проверены два мира, `20261111` и `20261112`. В обоих квадрокоптер обнаружил 3 опоры и 12 изоляторов с правильными цветами, выполнил один взлёт и одну посадку после возврата к старту. Максимальные ошибки определения центров опор составили 0,014 м и 0,011 м соответственно. В записанном прогоне проверена публикация обоих видеопотоков, обоих `camera_info` и всех трёх преобразований TF.
